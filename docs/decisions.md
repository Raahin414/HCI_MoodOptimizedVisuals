# Implementation decisions

- Revised user requirement (2026-11-24): camera expression suggestions replace text input on `/adapt`, overriding the original document's camera prohibition for the personal workspace. The randomized study remains self-report based. See camera-workspace.md for the local model, mappings, provenance and verification boundaries.

- Local-only implementation follows the specification's offline SQLite/Node requirement. Sites hosting uses a different server runtime; registration/publication is outside this local research-software deliverable.
- Node 24 LTS built-in `node:sqlite` avoids native compilation on Windows. SQLite is experimental in Node 24 and emits its standard warning. No cloud or Python is needed for the app.
- Fixed fictional reference day 2026-11-18 makes scoring reproducible. The workspace clearly labels the scenario date. Calendar navigation exposes all fixture dates.
- Style: editorial-greeting, draw seed 1968611802, no redraws. A pale sage paper-like frame and bundled Instrument Sans/Serif take the face from a student study desk. The product-specific element is eight views of the same academic work; course progress and completion counts are computed from fixtures. The serif has one job: the overview/check-in/briefing title. Layout difference is required by the study and overrides a single uniform dashboard composition.
- Gallery previews are raster captures of the actual eight local renderers, generated by `scripts/capture-previews.mjs`. They are illustrative previews, not placeholder workspaces; the separate workspace routes remain fully functional. This also avoids rendering hundreds of inaccessible tiny DOM controls inside the gallery.
- Shared task/course utilities preserve parity and keyboard access across all eight structures. They may attenuate measured layout differences if participants rely on them; navigation events allow this to be reported. The eight assigned tasks rotate four deadline examples and four completion examples; other computable task families are in the task bank for protocol extensions, but are not assigned in version 1.0.
- Offline text-model evaluation is implemented; deployed automatic inference is optional and requires explicit configuration plus the validated portable-artifact gate described in model-deployment.md. The immediate demonstration and conversational guide use local deterministic rules. No model metrics, confidence, human mood superiority or adaptation benefit is invented.
- Automated DOM/layout checks and desktop Chromium runs are software checks. A phone viewport is not real-device or screen-reader certification. A human 6–8-person rehearsal and institutional review remain necessary before external recruitment.
